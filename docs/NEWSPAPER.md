# Управление газетой

Раздел редакционной админки: `/newspapers`. Публичный архив: `/{locale}/gazeta`.

1. Нажмите **Создать выпуск**, укажите номер, адрес, название, месяц и язык. Адрес фиксируется после создания; `01` занят исходным импортированным выпуском.
2. Выберите опубликованные статьи. Стрелки меняют порядок полос; корзина убирает статью из выпуска. Одна статья добавляется в выпуск один раз, максимум 80 статей.
3. Загрузите обложку. Кнопка фотографии у статьи задаёт отдельное фото этой полосы. Перед загрузкой укажите автора изображения и права. Поддерживаются JPEG, PNG, WebP и GIF до 10 МБ. Без замены используется фотография опубликованной статьи.
4. Сохраните черновик и откройте **Предпросмотр**. Он доступен только сотрудникам редакции с активной сессией и закрыт от индексации.
5. Главред или администратор нажимает **Опубликовать** и подтверждает номер. Он появляется в публичном архиве сразу, без пересборки приложения.

Опубликованный номер содержит отдельные копии текстов и фотографий. Правки статей и правки черновика выпуска не изменяют номер в архиве. Для обновления сохраните выпуск и опубликуйте его повторно. **Снять с публикации** удаляет номер из публичного архива, сохраняя редакционный черновик.

Сервер проверяет права, CSRF и `expectedRevision`. Устаревшие сохранения и публикации возвращают 409; интерфейс предлагает обновить данные. Неопубликованные статьи нельзя включить в опубликованный выпуск. Публикация и снятие фиксируются в журнале.

## Основное локальное окружение

- Редакционная админка: http://localhost:6868/newspapers
- Публичный архив: http://localhost:3002/ru/gazeta
- Общий API: http://localhost:5555/api/creata/v1

Газета использует основную базу, указанную в корневом `.env` (`DATABASE_URL`). Запуск актуального API из корня: `bun scripts/run-api.ts` (без `--test-db` и без подмены `CREATA_API_BINARY` на старую сборку). Основной сайт и админка уже настроены на этот API; опубликованные номера доступны без пересборки.

## API

- `GET/POST /api/creata/v1/admin/newspapers`
- `GET/PATCH /api/creata/v1/admin/newspapers/{id}`
- `GET /api/creata/v1/admin/newspapers/{id}/preview`
- `POST /api/creata/v1/admin/newspapers/{id}/publish`
- `POST /api/creata/v1/admin/newspapers/{id}/unpublish`
- `GET /api/creata/v1/public/newspapers`
- `GET /api/creata/v1/public/newspapers/{slug}`

Хранилище: существующий PostgreSQL, документы `newspaper_issue` и `newspaper_publication`. Загрузка изображений использует общий `/admin/media` и настроенное S3-хранилище (локальный каталог только в разработке). Контракты находятся в OpenAPI и генерируются командой `bun run contracts`.

Первоначальный выпуск №01 сохраняется в архиве как самостоятельное импортированное издание. Новые номера управляются через админку.

## Проверка реализации

Проверены PostgreSQL-тесты приватности, прав, конфликтов, порядка статей и независимых снимков. Браузерный сценарий проходит создание, выбор и перестановку статей, реальную загрузку обложки и фото статьи, сохранение, закрытый предпросмотр, публикацию, сохранность старой версии и снятие с публикации. Ещё четыре сценария проверяют исходный №01, язык интерфейса, клавиатуру и размеры 360/768/1440 px. Сборки сайта и редакционной админки проходят.

Затем управление газетой подключено к основной базе: API обновлён на 5555, админка работает на 6868, сайт — на 3002. Старый кэш маршрутов основного Next.js сохранён в `.runtime` и заменён новым, чтобы открывались вновь созданные номера.

На основной базе повторно проверен полный сценарий создания, загрузки фотографий, предпросмотра, публикации, изменения черновика и снятия с публикации.
